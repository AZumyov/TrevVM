TrevVM

A Linux desktop running in a container. This page is a local reference; it does not require internet access.

Where your files live

Your home directory inside the desktop is mounted from the host's Save/ folder. Files there survive restarts, rebuilds and updates. Everything outside it is part of the image.

Run these in the Codespaces terminal

Not inside the desktop. The control script lives in the repository checkout.

CommandWhat it does
./trevvm.sh statusContainer state, health, URL, save path.
./trevvm.sh logs -fFollow the desktop logs.
./trevvm.sh backupArchive Save/ into backups/.
./trevvm.sh update --checkShow incoming commits without rebuilding.
./trevvm.sh updatePull, rebuild and recreate; keeps Save/ and snapshots the old container.
./trevvm.sh doctorCheck Docker, KVM, port, disk and save state.

Adding apps

./trevvm.sh apps list
./trevvm.sh apps install vlc

Apps installed this way live in the container. Run ./trevvm.sh snapshot afterwards if you want to keep the changed system across an update.

Snapshots

./trevvm.sh snapshot my-setup
./trevvm.sh snapshots
./trevvm.sh use trevvm:my-setup

A snapshot is a Docker image committed from the running container. It preserves apt-installed software and system changes, but not Save/ (that is already persistent).

Panic key

The optional panic key is a browser-side userscript or bookmarklet. Open panic.html from the repository, or run ./trevvm.sh panic in the terminal and open the printed URL. It is not installed into the desktop.

If the desktop feels slow

Rebuild with a lighter desktop: ./install.sh --reinstall --de xfce -y. KVM acceleration is used automatically when the host exposes /dev/kvm.
